# Aiscribe 引导页 · 六屏向导改版提示词

> 用途：把现有单页引导页（`ai_report/web/index.html`）改造成「启动画面 → 四步向导 → 生成等待页」的六屏应用。
> 本提示词由一份「电影感太空旅行落地页」提示词改写而来：**保留它的液态玻璃设计系统与动画节奏，替换掉所有与本项目无关的部分**（营销落地页结构、视频背景、假进度）。

---

## 〇、总纲（第一条发送）

你要改造一个**本机运行的 AI 工作总结工具**的引导页。它跑在 `127.0.0.1`，数据全部来自本机，不联网、不上传。请把它从一个长页面改造成**六屏向导**：

```
Splash 启动屏 → ① AI 工具选择 → ② 时间选择 → ③ 对话选择 → ④ 模板选择 → Generating 生成等待页
```

技术栈（CDN，版本锁定，不要替换或升级）：

```html
<script src="https://cdn.tailwindcss.com"></script>
<script src="https://unpkg.com/react@18.3.1/umd/react.development.js"></script>
<script src="https://unpkg.com/react-dom@18.3.1/umd/react-dom.development.js"></script>
<script src="https://unpkg.com/@babel/standalone@7.29.0/babel.min.js"></script>
<script src="https://unpkg.com/framer-motion@11.11.17/dist/framer-motion.js"></script>
```

> 注意：这一版 `framer-motion.js` 暴露的全局名就是 `Motion`，**不存在 `FramerMotion`**。
> 不要写 `window.Motion = window.FramerMotion;`（会把库覆盖成 `undefined` 直接白屏），直接引用 `window.Motion`。
> 另外 `@babel/standalone@7.29.0` 处理 `<script type="text/babel">` 用的是 classic JSX（`React.createElement`），
> 不要给该 script 标签加 `data-presets`，默认行为已正确。

结构：`body` 背景 `#000` 起步（实际由下面的光晕层覆盖），页面是挂在 `#root` 上的 React 应用，所有组件写在 `<script type="text/babel">` 里，通过 `window.X = X` 导出。

### 本项目的硬边界（必须遵守）

1. **只改前端**。后端接口（`ai_report/ui.py` 暴露的 HTTP 接口）一行都不许改，也不许新增接口。
2. **不加视频**。不引任何 mp4 / 外链媒体资源。背景全部由 CSS 生成。
3. **不做假进度**。等待页的进度必须绑定真实发生的工作，见第七节。
4. **不引额外库**。只用上面五个 CDN + 现有接口，不要加 lucide、axios、swr、zustand 之类。
5. **MCP 内核不动**。`ai_report/mcp_server.py` 与本页无关，禁止改动。
6. **现有功能一个都不能丢**：逐源扫描、按项目勾选、时间剪辑（含撤销）、格式模板、输出格式、复制指令。

## 三、背景层（纯 CSS，替换掉原提示词的视频）

## 五、Stepper 与屏间过渡（本页动效的主轴）

### Stepper（一直可见，位于顶部栏下方）

`1-2-3-4` 四个序号 + 连接线，每个序号三态：

- **未到达**：细边框玻璃圆，次文字色
- **当前**：品牌绿实心圆，白字，外圈一圈 `box-shadow` 光晕（呼吸动画，1.6s 循环）
- **已完成**：品牌绿描边 + 勾号，连接线变品牌绿（用 `scaleX` 从 0 到 1 的动画补齐，250ms）

**顺序锁定**：只有「已完成」与「当前」可点；未到达的步骤 `cursor: not-allowed` 且点击无效。可以**回退**（回退后其后的步骤标记为未完成），但**不能跳步**。

### 屏间过渡

用 Framer Motion 的 `AnimatePresence mode="wait"` + `custom={direction}`：

| 方向 | 进入 | 退出 |
|---|---|---|
| 前进 | 从 `x: 32` → `0`，`opacity: 0 → 1`，`filter: blur(10px) → 0`，320ms `easeOut` | `x: 0 → -24`，`opacity → 0`，220ms |
| 后退 | 从 `x: -32` → `0`，其余同上 | `x: 0 → 24`，`opacity → 0`，220ms |

`mode="wait"` 保证旧屏退完再进新屏，避免两屏重叠。整屏过渡总时长控制在 550ms 内。

### 屏内入场（原提示词的节奏直接沿用）

每个屏的内容元素用统一的入场参数：

```js
initial: { filter: 'blur(10px)', opacity: 0, y: 20 }
animate: { filter: 'blur(0px)',  opacity: 1, y: 0 }
transition: { duration: .6, ease: 'easeOut', delay }
```

同屏内元素按 `0.05 / 0.12 / 0.2 / 0.28` 秒递进延迟，不要用原来那种 0.4~1.4s 的大延迟（工具页不能让人等）。

### BlurText（逐词模糊入场）

保留原提示词的实现：`IntersectionObserver` 触发（阈值 0.1），按空格分词，每词 `motion.span`，三段 keyframes：

```js
initial: { filter: 'blur(10px)', opacity: 0, y: 50 }
animate: { filter: ['blur(10px)','blur(5px)','blur(0px)'],
           opacity: [0, .5, 1], y: [50, -5, 0],
           transition: { duration: .7, times: [0, .5, 1], ease: 'easeOut',
                         delay: (i * 100) / 1000 } }
```

`display: inline-block; marginRight: 0.28em`（**不要用 nbsp**，负 letter-spacing 会把 nbsp 吃掉）。父级 `display:flex; flexWrap:wrap; justifyContent:center; rowGap:.1em`。

**只用在两处**：Splash 的品牌标语、等待页的阶段大标题。别滥用，工具页每屏都逐词模糊会显得很慢。

## 六、四个步骤屏（每屏绑定的现有接口）

### 屏 ① AI 工具选择

- 标题：`选择要读的 AI 工具`
- 列表项 = 本机检测到的数据源。`GET /api/sources` → `[{ name, content_level, available }]`
- **逐源真实扫描**（这是白捡的高级感，天然可动画）：对每个 `available` 的源**串行**请求 `GET /api/source?name=<name>` → `{ name, content_level, available, count }`；每返回一个，该项从"待扫描"变成"已点亮"（玻璃项 + 品牌绿勾 + `count` 数字滚动到位），并显示 `content_level`
- 不可用的源显示为禁用态并标注"未检测到"，不参与扫描
- 全部扫完前「下一步」禁用，并显示 `已扫描 n / m`
- 底部小字：`数据全程本机，只读不写`

### 屏 ② 时间选择

- 三个分段控件（胶囊玻璃）：`日报` / `周报` / `自定义时间`
- `日报`：一个日期框；`周报`：一个日期框（= 该日期所在自然周，界面要显示解析出的 `起 ~ 止`）；`自定义时间`：`从` / `到` 两个日期框
- 「下一步」的可用条件：日报/周报要有日期；自定义时间要 `start <= end`
- 起止自动纠偏（起点晚于终点时把终点拉过去），切进自定义时间默认近 7 天
- 请求：`GET /api/conversations?mode=<daily|weekly|range>&date=<YYYY-MM-DD>` 或 `&start=&end=`
- 摘要条：显示窗口内 `total_records` 条会话、`projects.length` 个项目

### 屏 ③ 对话选择

- `GET /api/conversations?mode=&date=/&start=&end=&detail=summary` → `{ total_records, projects:[{ project, count, records:[...] }], range }`
- 按项目分组的泳道，每条记录是一个玻璃 chip（显示 `time`、`title`、`source`）
- 默认全选；顶部有 `全选` / `全不选` / `清空全部剪辑`
- **时间剪辑**：每个 chip 右侧一个剪刀按钮（点击不冒泡到"勾选"），点开居中的玻璃「剪辑台」面板，两个 `type="time"` 输入 + `保存剪辑` / `清除这条剪辑` / `关闭`
  - 保存：`POST /api/trim { id, start, end }` → `{ id, trim, count }`；两端都空 = 清除
  - 清空全部：`POST /api/trim { clear: true }` → `{ cleared, count }`
  - 已剪辑的 chip 打「已剪辑」徽标 + 虚线边框；`trim` 字段从返回里读回并恢复状态
- **已剪辑的语义要在界面上讲清楚**（这是工具侧真实生效的裁剪，不是提示词提醒）：`窗口外的片段已被工具丢弃，AI 看不到`
- 底部显示 `已选 n / m 条`，可点「下一步」

### 屏 ④ 模板选择

- `GET /api/templates` → 模板数组（含 `name` 与 `style`）
- 每个模板一张玻璃卡：显示模板名、规范文本 `spec` 的前几行、`sample_count`
- 选中后 `GET /api/template?name=<name>` → `{ name, spec, image_hint, sample_count, pending_vision, style }`，右侧实时渲染**报告骨架预览**（按 `style` 渲染 `1、项目名：` + `①、事项` 的骨架，条目文字用占位短句，不要用真实会话内容）
- `pending_vision: true` 时提示：`这是图片样例，需要让 AI 读图后回填`
- **格式克隆上传**：支持拖拽 md / txt / docx / 图片，逐文件读成 base64 后 `POST /api/learn { files:[{name,data}], name }`，成功后刷新模板列表并自动选中新模板
- 输出格式三选（胶囊）：`Markdown` / `Word` / `可分享 HTML`
- 「生成」按钮：`POST /api/instruction { ids, mode, date, start, end, format, template }` → `{ text }`；拿到 `text` 后进入等待页（见第七节），完成后提供 `复制指令`

## 七、Generating 生成等待页（进度必须是真的）

**这一屏是本页的门面，但绝不许造假。**

本工具的报告正文由**用户自己的 AI 客户端**（通过 MCP 读取素材）来写，本机并没有"生成报告"这个进程。所以等待页展示的必须是**本机真实做的工作**，按下面的真实阶段推进：

| 阶段 | 真实触发的请求 | 界面表现 |
|---|---|---|
| 1 读取素材 | `GET /api/conversations?...&detail=full`（真实耗时：读全量原文） | 环形进度旋起，副标题 `正在读取本机对话原文` |
| 2 按项目聚合 | 用上一步返回的 `projects` / `total_records` 统计 | 数字滚动到真实值，阶段行打勾 |
| 3 套用模板 | `GET /api/template?name=<name>`（未选模板则跳过并标注「未套模板」） | 阶段行打勾 |
| 4 生成指令 | `POST /api/instruction {...}` | 阶段行打勾 |
| 5 素材就绪 | —— | 大标题换成 `素材已就绪，交给你的 AI` |

要点：

- 环形进度用 `stroke-dashoffset` 动画，进度值 **= 已完成阶段数 / 总阶段数**；因为阶段数少，视觉上要补一个**不定态旋转弧**避免"一格一格跳"，但**不许写死一个假百分比**，也不许长时间卡在 90%
- 阶段列表逐行出现：未开始（次文字）/ 进行中（品牌绿 + 旋转小圈）/ 已完成（勾号 + 计数）
- 第 2 阶段的数字用 BlurText 或数字滚动，显示真实的会话条数
- 任一阶段出错：停下，显示错误原文 + `重试` 按钮，**不要默默跳过**（后端出错时返回 `{"error": "..."} 400`）
- 第 5 阶段完成后：显示 `生成报告`（主 CTA，`POST /api/generate`，本机渲染 + 按需 LLM 归纳并落盘 `reports/`；成功后给文件名 / 路径 / 条数 / 项目数 + 是否真的归纳过 + 打开与下载链接）+ `复制指令`（调 `navigator.clipboard`，复制成功给一次轻量的按钮形变反馈）+ `返回修改` 按钮
- 若用户选了 Word / HTML：`生成报告` 时本机真的写出对应文件（`GET /api/report?name=X` 取回）；
  走 `复制指令` 那条路时，额外提示 `落盘由 AI 客户端调用 save_report 完成`，不要在本页假装写文件

> 2026-10-17 追加：原规格第 5 阶段只提供「复制指令」。用户要求「走完向导就直接出报告」，
> 于是新增 `POST /api/generate`（按勾选 ids + 剪辑过滤素材 → 渲染 → 按需 LLM 归纳 → 落盘）与
> `GET /api/report`（取回成品），等待页同时保留「复制指令」这条质量更高的路径。
> 这一条**突破了原规格「不要改后端接口」的限制**（那是上一轮改版的范围约束），属用户新提的能力。

> 2026-10-17 追加二：「纯模板」并不做任何语义归纳 —— 它把 `rec.summary`（对 CodeBuddy CN 就是
> 当日真实输入时间线）当正文排版，所以出来看着就是「对话堆砌」。据此等待页又多了：
> `GET /api/llm`（归纳能力状态）+ 等待页的「AI 归纳」开关（默认开），`POST /api/generate`
> 因此接受 `polish` 参数；**归纳成功/退回草稿都必须在结果卡上如实标注**，未配置 key 时不许
> 假装归纳，要给出「配在哪」的指引。
