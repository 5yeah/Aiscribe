# 数据源适配：新增一个 AI 工具的读取器

`aireport` 的分层是 **L1 连接器 → L2 统一索引与分类 → L3 报告生成 → L4 可选能力**。
新增一个数据源，只需要在 L1 加一个文件，其余层不用改。

## 一、已内置的数据源与“内容等级”

全部为**原生实现**：直接读工具自己的本地文件，不依赖 Cass 之类的第三方索引器。
`common.py` 提供 zstd 解压、JSONL 读取、ISO 时间解析、正文块抽取、注入上下文过滤等公共工具。

### 逐条原文

| 数据源 | 本地位置（自动发现） | 本地能拿到什么 |
|---|---|---|
| CodeBuddy CN | `%APPDATA%/CodeBuddy CN/codebuddy-sessions.vscdb` + 同目录 `logs/**/*.log` | 会话元数据；**logs 里 `onAgentStart: userInput=` 事件可还原当天真实发送的用户输入（逐条全文）** |
| TRAE | `~/.trae-cn/memory/projects/<项目>/<yyyymmdd>/session_memory_*.jsonl`、`topics.md` | 逐条 message 级摘要 + 会话级 topics 摘要 |
| Codex | `~/.codex/state_5.sqlite`、`thread_history_1.sqlite`、`sessions/**/rollout-*.jsonl.zst` | 线程元数据 + 逐条 user/assistant（投影历史优先，zstd rollout 兜底） |
| dsh | `~/.dsh/sessions/<cwd>/session-<uuid>/session.v4.jsonl.zstd` | 事件流里的逐条真人输入（多 zstd 帧，`source.kind=user` 才是真人） |
| Claude Code | `~/.claude/projects/<编码 cwd>/*.jsonl` | 逐条 user/assistant（跳过 `isSidechain` 子代理与 `<command-name>` 噪音） |
| Gemini CLI | `~/.gemini/tmp/<hash>/chats/session-*.json` | 逐条 user/gemini 消息 |
| Qwen Code / iFlow | `~/.qwen` / `~/.iflow` 同结构 | Gemini CLI 分支，同一解析器 |
| Copilot Chat | `%APPDATA%/Code/User/workspaceStorage/*/chatSessions/*.jsonl` + `chat.ChatSessionStore.index` | 内建聊天逐条请求（无正文时退化为仅标题） |
| Cline / Roo / Kilo | `…/globalStorage/<插件 id>/tasks/<taskId>/api_conversation_history.json` | 逐条消息（三者为同源插件，格式一致） |
| Cursor | `%APPDATA%/Cursor/User/globalStorage/state.vscdb` 的 `cursorDiskKV` | `composerData:*` + `bubbleId:*` 逐条消息 |

### 仅标题 / 元数据

| 数据源 | 本地位置 | 本地能拿到什么 |
|---|---|---|
| 豆包 | `%LOCALAPPDATA%/Doubao/User Data/Default/IndexedDB`（LevelDB） | 会话标题与时间（V8 序列化 blob，需专用解析） |
| WorkBuddy | `~/.workbuddy/workbuddy.db` | 会话标题与时间（正文在云端） |
| Kimi | `%APPDATA%/kimi-desktop/kimi-agent/*.json` + `logs/main.log` | 元数据 + 被编辑文件路径（据此定位项目目录） |

> 内容等级决定报告质量：能取到“逐条真实输入”的源可以生成**内容级**日报；
> 只有标题的源只能贡献“任务列表级”线索。新增连接器时，**尽量把逐条原文塞进 `raw["messages"]`**。
>
> **zstd 说明**：Codex 与 dsh 的会话是 zstd 压缩的。装了 `zstandard` 包或系统有 `zstd` 命令就读到正文；
> 都没有时自动退化为「只读元数据 + 警告一次」，核心功能仍然是零三方依赖。

## 二、UnifiedRecord 字段约定

```python
UnifiedRecord(
    source="YourTool",        # 报告“数据来源”里显示的名字
    session_id="唯一 id",      # 同源内唯一即可（跨天会话建议拼上日期，见下文）
    title="会话标题",          # 可作为 summary 的兜底
    project="",               # 一律留空！由 L2 统一分类
    status="completed",       # 原始值即可，L2 会归一成“已完成/进行中”
    cwd="D:/project/xxx",     # 有项目目录就填，L2 用末段目录名兜底分类
    start_ts=..., end_ts=..., # epoch 秒（parse_ts 可识别毫秒）
    summary="一句话时间线",     # summary 模式下展示的内容
    raw={...},                # 原始字段备份；raw["messages"] 是给 AI 归纳的正文
)
```

`raw["messages"]` 的形状（**必读**）：

```python
raw["messages"] = [
    {"ts": 1791511200.0, "role": "user",      "text": "把副本数改成 3"},
    {"ts": 1791511260.0, "role": "assistant", "text": "已改 app.yaml 的 replicas: 3"},
]
```

- **两个角色都要收**。只留 `user` 的话，报告只能看出「问了什么」，看不出「做了什么」——
  这是报告质量的天花板。
- `summary` 仍然只渲染**用户侧**时间线（人看的是诉求），别把 assistant 的回复混进去。
- 用 `common.messages_payload(messages, day=..., limit=2000)` 生成，它会按自然日切分并按条截断。
- 单条截断到 2000 字符左右，别让 `raw` 无限膨胀。

**时间语义**是这套工具最容易踩的坑：

- `start_ts` = 该记录对应工作**开始**的时刻，`end_ts` = 最后一次活动时刻。
- `L2.filter_by_date` 的判定是：**起始落在窗口内**，或“窗口前创建、**跨度 ≤ 1 天**且窗口内仍在活动”。
  这样既能收进跨夜会话，又不会把一周前只被碰过一次的旧会话算进今天。
- 因此**跨天续聊的会话要按天拆成多条记录**（TRAE 连接器就是这么做的：
  `session_id = f"{sid}:{yyyymmdd}"`），否则昨天的内容会混进今天的日报。

## 三、三步接入

1. 复制模板：`examples/connector_template.py` → `ai_report/connectors/yourtool.py`
   （只实现 `available()` 与 `read()` 两个方法；zstd / JSONL / 时间 / 正文抽取直接用 `connectors/common.py`）
2. 注册：在 `ai_report/connectors/registry.py` 的 `REGISTRY` 里追加 `YourToolConnector()`
3. 补默认路径：在 `ai_report/config.py` 的 `default_paths()` 里加一行
   `"YOURTOOL_DB": _pick([h.joinpath(*YOURTOOL_REL) for h in homes]),`
   并在文件顶部声明相对位置常量。**不要写死用户名**，一律基于 `%APPDATA%` / `%LOCALAPPDATA%` / 用户主目录推导。
   多目录型数据源用 `_dirs([...])`（分号分隔、只收存在的目录），可参考 `VSCODE_USER_DIRS`。

## 四、分类（可选，不配也能用）

项目的归属优先级：`projects.json` 的 `rules` 关键词 → `title_hints` 标题关键词 → **cwd 路径末段目录名** → `其他`。
也就是说**新项目不改任何配置也会自动归类**，只要会话的 `cwd` 指向项目目录。
想固定项目名或合并同义叫法时，复制 `projects.example.json` 为 `projects.json` 再改即可
（也可放 `~/.aireport/projects.json`，或用环境变量 `AIREREPORT_PROJECTS` 指向任意位置）。

## 五、自测

```powershell
python -m ai_report sources                 # 应出现你的源，且 [available] 会话数 > 0
python -m ai_report config                  # 确认路径自动发现正确（不需要改代码）
python -m ai_report daily --date <某天>      # 看报告里有没有你的源的数据
python -m unittest discover -s tests -t .   # 加一个临时夹具测试，跑全量单测
```

## 六、隐私红线

- 连接器**只读本地文件**，绝不联网；正文取不到就只用元数据，不要为了内容去调用云端接口。
- 只读**当前用户**的目录。默认路径推导已按此收口（`config.scan_all_users()` 默认 False），
  新连接器不要自己去枚举 `C:\Users\*`。
- `read()` 里不要打印正文到 stdout（MCP 用 stdout 传协议，日志一律走 `utils.log` → stderr）。
- `reports/`、`projects.json`、`dingtalk_config.json`、`automation.json` 已在 `.gitignore` 中，不要提交。
